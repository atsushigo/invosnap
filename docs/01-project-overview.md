# 01. 專案總覽與範疇

## 背景

- 本專案協助川醉湘（麻辣烫/滷味連鎖）某台灣分店評估「進貨單自動化建檔」的可行性，店長是主要使用者與資訊來源。
- 總部POS系統功能有限，且總部目前沒有資源為單一分店客製開發新功能。
- 店長希望先有一個「店內自建的輔助工具」，不依賴總部排期。

## 現況痛點

- 每天最多約 5 家供應商送原料，每家供應商一天約開出 3 張紙本進貨單。
  - 換算：尖峰情境下單日最多約 15 張紙本單據。
- 單據格式：類似 A4 大小、每家供應商「自己固定」的版式（非全店統一格式），內容包含：
  - 供應商/廠商別
  - 品項名稱（如：青江菜、小白菜…）
  - 單價
  - 數量／重量（單位依供應商不同：台斤、公斤…）
- 目前作法：店長手動把紙本資料一筆筆輸入POS，耗時、易誤植（尤其單位換算容易出錯）。
- 目標是把這些單據轉換成「店內系統統一單位、統一格式」的進出貨資料，最終寫入（或匯入）POS。

## 使用者與角色

| 角色 | 說明 |
|---|---|
| 店長（主要使用者） | 每日收貨時用手機拍照上傳單據、覆核辨識結果、確認入帳 |
| （未來）加盟業主/總部 | 若擴散到其他分店，可能需要多店/多帳號管理 |
| 供應商 | 被動角色，不使用系統，只是單據格式的來源（每家格式可能不同、也可能不時微調） |

## 目標（Goals）

1. 用手機拍照取代手動輸入，減少每日鍵入紙本資料的時間。
2. 自動辨識供應商別、品項、單價、數量/重量，並依供應商對照表換算為店內統一單位。
3. 產出可匯入 POS（或未來可 API 串接）的進出貨資料。
4. 保留「人工覆核/修正」步驟，辨識結果不強制自動入帳，降低誤判風險（尤其金額類資料）。

## 非目標（Non-goals，先不做）

- 不重做/取代總部 POS 系統本身。
- 不假設一開始就有 POS API 可寫入——先以「產出標準化資料（CSV/Excel/資料庫）」為主，POS 串接視總部配合度而定（見 [04](04-roadmap-open-questions.md)）。
- 不處理付款、對帳、財務報表等延伸功能（MVP 範圍外）。
- 不支援供應商自行登入系統（單據來源仍是紙本）。

## 成功指標（暫定，待與店長確認）

- 每日建檔時間從「手動輸入」大幅縮短（例如目標：每張單據辨識+覆核 < 1 分鐘）。
- 品項/單價/數量辨識正確率達到「覆核微調即可」的水準（不需要整筆重打）。
- 供應商單位換算 100% 依對照表正確換算（這塊不能靠OCR猜，需明確規則表，見 [03](03-architecture-proposal.md)）。

## 已知風險

- 供應商單據格式不統一，且可能會變動（缺乏「一張範本走天下」的假設基礎）。
- 手機拍照品質不穩定（光線、歪斜、皺褶紙張），影響辨識率。
- 單位換算是「業務規則」而非影像辨識能解決的問題，容易被忽略但其實是專案的核心正確性風險。
- 若最終要寫回POS，需視POS是否有可用的匯入/API管道，這點目前未知（待確認，見 [04](04-roadmap-open-questions.md)）。
