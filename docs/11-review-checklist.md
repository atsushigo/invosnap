# 11. 待你 Review 的事項清單（2026-09-02）

盤點目前整個專案，哪些地方需要你檢查/拍板才能繼續往下走。分成「一定要你決定」跟「我已經有建議、你確認就好」兩類。

## 一、雲端部署：建議跟既有正式環境分開機器

你提到上雲要用 Hetzner，因為side projects都部署在那邊、比較便宜。這個方向沒問題，但有一個**重要風險點要先跟你確認**：你另外有一台Hetzner伺服器正在跑別的專案的正式環境（服務真實使用中），**建議InvoSnap不要跟它共用機器**——兩個專案完全不相關，一旦InvoSnap這邊出問題（例如吃太多記憶體、當機）沒必要拖累到正式環境。Hetzner的入門級機型（CX22等）月費約€4~5，額外開一台新機器專門跑InvoSnap、兩邊完全隔離，成本可以忽略。

> 這點我**認為需要你明確拍板**，因為涉及是否要花錢開新機器。

## 四、本機MVP已完成第一版並測試通過（2026-09-02更新）

依你「先本地部署，之後平移到Hetzner」的指示，已經把MVP骨架做出來並測過一輪：

- **後端**（`backend/`）：Node.js + Express + SQLite，實作了 [03](03-architecture-proposal.md) 的資料模型，啟動時自動載入 `data/` 種子資料。API涵蓋拍照辨識、單據列表/詳情、覆核修正、確認入帳、CSV匯出。
- **前端**（`frontend/`）：Vue 3 + Vite，三頁（拍照上傳／單據列表／覆核頁），覆核頁有信心度標記、品項對應下拉選單、明細金額跟單據總額對不上時的警示。
- **測試方式**：後端用curl測過完整流程（列表→覆核修正→確認入帳的409/200狀態轉換→CSV匯出，中文正確顯示）；前端用Playwright寫了一支17項檢查的自動化測試腳本，涵蓋頁面導覽、下拉選單互動、checkbox勾選、確認入帳的成功/失敗分支、重新整理後資料有沒有真的持久化——**17項全部通過**，瀏覽器也沒有非預期的console錯誤。
- **唯一沒測到的部分**：`POST /api/receipts/recognize` 實際呼叫Claude Vision API辨識這件事本身——因為要花真的API費用，遵照你先前「盡量不要花錢」的指示沒有執行；已驗證的是這支API在沒有API key時會回傳清楚的502錯誤而不會讓伺服器崩潰，程式邏輯本身沒有問題。等你想正式測，填好 `backend/.env` 的 `ANTHROPIC_API_KEY` 就能跑。
