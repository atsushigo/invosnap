# 04. MVP 路線圖與待確認事項

> **更新（2026-09-02）**：以下1~5項已在本機完成第一版實作並用Playwright自動化測試通過，見 [backend/](../backend)、[frontend/](../frontend) 與根目錄README「快速開始」。拍照辨識本身因為要花真的API費用而未實測，其餘（覆核、對照、確認入帳、CSV匯出）已全部驗證。

## MVP 範圍建議（第一版做到哪）

1. Vue 拍照上傳頁（單張照片上傳）。✅ 已實作（`frontend/src/views/UploadView.vue`）
2. Node.js 後端呼叫 LLM Vision API，回傳結構化品項清單。✅ 已實作（`backend/src/vision.js` + `POST /api/receipts/recognize`）
3. 基本供應商/品項對照表（先手動建幾家常用供應商與品項，不求一開始就自動比對完美）。✅ 已實作，種子資料見 [09](09-store-item-master-and-vendor-mapping.md)
4. 覆核頁：店長可修改辨識結果、指定/新增品項對照、確認換算後數量正確。✅ 已實作（`frontend/src/views/ReviewView.vue`），含信心度標記與明細金額對總額的落差警示
5. 確認後存入 SQLite，並可匯出當日/當週 CSV。✅ 已實作（`GET /api/receipts/export/csv`，內部標準格式見07模組四）

**先不做**（等MVP驗證可用後再排）：
- 多張連續拍照/批次處理
- 自動比對「這張單價跟上次進貨差多少」等進階分析
- 與POS的自動API串接（除非確認POS支援，見下方待確認事項）
- 多分店/多帳號權限管理

## 待確認事項（需要店長/相關人員提供資訊，才能把架構訂得更準）

1. **POS系統是不是有「匯入」功能？**（例如支援匯入CSV/Excel建立進貨單）還是完全沒有任何匯入管道，只能靠人工在POS介面重打？這會決定「匯出」這一步的最終格式要對齊什麼規格。
2. **POS系統廠牌/名稱是什麼？** 若之後要接觸廠商詢問是否有API或匯入格式文件，需要知道是哪套系統。
3. **供應商單據範例**：能否取得每家供應商（最多5家）近期的實際單據照片各1~2張（可去識別化敏感資訊如聯絡電話等），用來實測LLM辨識穩定度、以及設計對照表初始資料。
4. **單位換算規則從哪來？** 是店長心裡有一套經驗值（如：1台斤=0.6公斤），還是供應商單據上其實有寫清楚單位，只是要店內統一顯示格式？這會影響 `VendorItemMapping` 初始資料要怎麼建。
5. **「新品項/新供應商」出現時的處理流程**：是否要求店長當下在覆核頁手動建立對照，還是先允許「未對照」狀態、之後再統一整理？
6. **資料存放位置偏好**：店內是否已有可跑Node.js服務的電腦/主機，還是希望部署在雲端（需要額外考慮每月主機費用、以及LLM API費用由誰負擔）？

## 下一步建議

- 先用第3點提到的少量真實單據照片，做一個「拍照→丟給LLM Vision API→看JSON輸出品質」的小型驗證（不需要完整系統，一支腳本即可），確認辨識可行性與常見錯誤模式，再決定是否照本文件的架構往下開發。
- 驗證通過後，再依 MVP 範圍表逐步實作。
